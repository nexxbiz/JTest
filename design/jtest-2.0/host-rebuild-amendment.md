# JTest CLI host rebuild — design amendment

Design identity: `pkid:design:jtest:cli-host-rebuild` version 1.0.0
Status: awaiting human approval. Amends the approved JTest 2.0 design
(`architecture-design.md` 1.0.0, approval in `review-manifest.json`) for
one bounded area: the generated console host. Everything else in the
approved design stays authoritative and unchanged.

## Why

Program Kit `773d7cf` supersedes the dispatcher-based console generation
JTest adopted at JT2-W070. The new typed console generation delivers the
architecture the human requested upstream: Spectre-based typed commands,
per-command handler and validator contracts, one CShells shell feature as
the single DI seam, sealed/attested generated trees, and offline
verification (`program-kit dotnet verify-host`) plus request-driven
regeneration (`program-kit dotnet refresh-host`). The old
`IProgramKitConsoleCommandDispatcher` contract no longer exists upstream.

**Application logic does not change.** `JTest.Language`, `JTest.Engine`,
`JTest.Reporting`, and the command implementations in `JTest.Cli` stay as
approved; this amendment covers only the host seam.

## New host architecture

### Consumer contracts (in `JTest.Cli`, human decision)

A new `Console/` intent area in the existing gated `JTest.Cli` library
(adds the pinned `CShells` 0.0.28 package reference):

| contract | shape |
| --- | --- |
| `JTestRunRequest`, `JTestValidateRequest`, `JTestDescribeRequest` | Typed immutable request classes mirroring the Open Console options/arguments. |
| `IJTestRunHandler`, `IJTestValidateHandler`, `IJTestDescribeHandler` | `ValueTask<int> HandleAsync(request, ct)`; implementations adapt the existing `RunCliCommand` / `ValidateCliCommand` / `DescribeCliCommand` unchanged. |
| `IJTestRunValidator` | Consumer validation for `run` (value-file existence, duplicate `--env` keys, parallel/timeout parsing) — moved out of `RunCliCommand` so invalid input exits 2 before the handler, in the host-owned uniform format. `validate`/`describe` register no validator (legal). |
| `JTestCliShellFeature : IShellFeature` | The single DI seam: registers handlers, the validator, and their services. |

### Generated host (`src/JTest.Cli.Host`, fully replaced)

The dispatcher-era tree (generated parser, dispatcher interface, consumer
glue, locks) is deleted and replaced by the new generation output: a
complete executable Spectre.Console.Cli project (pinned CShells 0.0.28,
Spectre.Console 0.55.0, Spectre.Console.Cli 0.55.0) with per-command
generated settings, request factories, and command classes
(`ctor(handler, validator?)`; validator failure → invalid-invocation exit
code, handler integer returned unchanged). The generated project
references `JTest.Cli` one-way; Spectre owns parsing and help.

### Generation inputs (`tools/JTest.HostInputs`, extended)

The tool authors, with exact digests: the Open Console document (grammar
unchanged: `run`/`validate`/`describe`, frozen exit map 0–3), the new
**binding document** mapping every command to the consumer request/
handler/validator/feature types in the compiled `JTest.Cli` assembly, and
the **generation request** consumed by `refresh-host`.
`tools/generate-cli-host.ps1` moves to the
`refresh-host --request … --build-consumer` flow.

### Integrity

`program-kit dotnet verify-host --root src/JTest.Cli.Host` joins the
acceptance suite: any tampering with generated bytes fails the build with
per-file verdicts. Regeneration is byte-deterministic for unchanged
inputs.

## Behavior preserved (acceptance bar)

The frozen CLI contract of the approved design is unchanged: commands,
options, exit codes 0/1/2/3 computed from evidence, always-printed
clickable report URL, auto-open semantics, `--diagnostics text|json`.
Existing process-level acceptance tests remain the bar; assertions bound
to dispatcher-era parser message prefixes (`PKNETC*`) are relaxed to exit
codes plus Spectre-rendered messages.

## Decisions and open items

- Contracts live inside `JTest.Cli` (human decision; alternative separate
  contracts project rejected as more moving parts).
- Open decision for approval: whether to also design a **consumer-owned
  analyzer** for the review-enforced governance rules (one type per file,
  fresh-receiver ban, writer purity). Not required by this design's
  invariants; see the gate design §5.
- Tool packaging seam (`PackAsTool`/`ToolCommandName jtest`) on the new
  generated project is a work-unit investigation item with a stop
  condition if the generation output leaves no consumer-owned hook.
